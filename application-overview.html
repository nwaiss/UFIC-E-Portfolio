Application Overview

The Princess Vlei Forum is a Cape Town non-profit dedicated to protecting the Princess Vlei wetland. Their website hosts general information alongside over 200 historical articles, and rather than asking visitors to search through all of that, every page on the site carries an embedded AI chatbot — the Princess Vlei Assistant. It appears as a floating button any visitor can open to ask plain-language questions about the forum, the vlei's history, local wildlife, conservation efforts, or how to visit, and get a direct answer instead of hunting through pages.

How It Is Built

The chatbot widget is a single self-contained JavaScript file — roughly 1,300 lines — with no framework, no build step, and no external dependencies. It constructs its entire user interface at runtime, which keeps the footprint small and ensures it loads reliably on any device. The broader site runs on Cloudflare Workers, an edge-computing platform that serves content from data centers geographically close to each visitor rather than from one central server — a practical and cost-effective choice for a small non-profit.

The AI backend is a separate Cloudflare Worker. When a visitor asks a question, the browser sends that message along with the last six messages of conversation history as a JSON payload to this backend, which queries an AI language model and returns a formatted response — including relevant links — rendered client-side through a hand-built Markdown renderer. The system prompt, knowledge base, and exact model configuration live in this external backend and were tuned specifically for the Princess Vlei Forum's content.

Key Engineering Decisions

AI-generated link safety. AI models can occasionally suggest incorrect or fabricated URLs. To prevent bad links from becoming clickable, every URL the AI returns is checked against a hardcoded allowlist of trusted domains. Links to unrecognized domains render as plain text rather than hyperlinks — the reference is still visible, but a visitor cannot accidentally click through to an unreliable source.

Cost and reliability. Rather than depending on a single AI provider, the backend runs a primary-to-backup fallback chain. If the main model is slow, over budget, or experiencing errors, the system automatically switches to a secondary provider. Users see a transparent “limited mode” notice rather than a silent failure — an honest and practical approach for an organization with a tight budget.

Context management and rate-limiting. To keep costs predictable, each request sends only the last six messages of conversation history rather than the full session. Visitors are assigned an anonymous per-browser identifier used server-side for rate-limiting, with no personal data collected or stored.

User Experience

A visitor lands on any page of the Princess Vlei Forum site and sees a floating green button in the bottom-right corner. Clicking it opens a chat panel with a greeting and four quick-question shortcuts covering the most common topics. They can select one or type their own question. A typing indicator appears while the response is generated, and the reply renders with formatted text and, where appropriate, safe clickable links. The conversation persists across multiple exchanges, and the panel can be closed and reopened at any time without losing the thread. The widget is auto-injected across all 230-plus pages on the site.

Testing

Automated tests cover the site's infrastructure — routing, admin authentication, and request handling. Conversational testing, including guardrails and off-topic edge cases, was conducted manually against the live backend. One guardrail is directly demonstrable: ask the chatbot about a source outside the trusted domain list and its link will appear as plain text rather than a hyperlink.
